# TikTok LIVE AR 设计参考

## 来源与适用范围

- 用户提供的 IMG_6658.PNG（1206 × 2622 图像像素）是观众视角的 TikTok LIVE 带货直播。以下 CSS 尺寸按截图约 3 个图像像素对应 1 个逻辑像素换算，均为**估算值**，不代表 TikTok 官方规范。
- [Effect House · Preview Panel](https://effecthouse.tiktok.com/learn/guides/workspace/panels/preview-panel) 展示手机形态预览、示例媒体或摄像头输入，以及中央录制按钮。录制交互来自此参考。
- [Effect House · Preview in Effect House](https://effecthouse.tiktok.com/learn/guides/publishing/preview-in-effect-house) 提供切换设备、模拟 TikTok 界面及检查安全区的流程。

## AR 叠加与安全区

- 顶栏、可拖动演示人物的舞台、底栏各占独立布局行。雨滴和烟花层限制在舞台内，不拦截触摸。
- AR 反馈放在舞台下方，用一行描述当前效果。表情控制可折叠。展开时由舞台让出空间，中央录制按钮保持在底栏。
- 预设三种表情供点按，拖动演示人物验证粒子碰撞随头部更新。录制按钮演示开始、计时、停止与完成反馈。
- 原型中的主播、观众与评论为演示内容，便于离线试用。

## 视口检查

在浏览器模拟 320 × 568、390 × 844、430 × 932 CSS px。表情面板展开且模拟录制进行时，三个尺寸的舞台分别高 368、644、732 px。底栏与舞台不重叠，反馈位于录制按钮上方，录制按钮完整可见，默认位置的头部没有被评论遮住。该检查使用浏览器视口模拟，未使用手机实机。

## 真人相机阶段

当前原型用真实前置相机代替演示人物。视频铺满舞台并水平镜像，星星叠层采用相同的裁切和镜像坐标。底栏保留非交互的表情识别状态与相机开关，错误与重试入口也放在底栏。上文的录制和模拟表情描述用于保留上一版原型的设计记录。

## 双端直播阶段

- 主播端 `/host` 与观众端 `/viewer` 是独立页面。直播视频铺满竖屏舞台，顶栏主播信息、左下评论、底部输入和礼物入口作为独立 UI 叠加。礼物入口仅占位。
- 评论最多保留最近四条，评论区有高度上限并滚到最新消息。底部保留安全区，输入与发送各自拥有独立触控区。
- 主播端将前置摄像头和脸颊星光合成为一条视频流。观众发送含 ✨ 的评论，主播端收到后触发约 3.4 秒的金白脸颊烟花，交替绽放，火星带拖尾下坠。直播和评论在同一浏览器、同一来源的两个页面之间传输。
